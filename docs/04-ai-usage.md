# 04 · AI 使用与个人贡献

## 如实声明

本项目采用AI辅助开发。Codex参与题目比较、方案、代码、测试、合成资料、实际运行、问题分析和文档编写。真实业务决策器接入DeepSeek；初次连接失败与首次评估汇总保留，后续实际完成模型验证和证据复核。

AI承担了：原生工具调用循环、参数及硬约束、SQLite幂等和断点、DeepSeek适配、离线规则模拟器、对抗与协议测试、场景评估脚本、文档。未使用其他子Agent，也未使用Agent框架。

候选人可确认的参与包括选择第2题、确认官方模型服务、在本地配置密钥、提出验收对齐与启动演示要求、要求重试真实连接、明确隐私边界与指定交付仓库。源码、自动化运行和本轮异常分析修复主要由AI协助完成。

## 验证范围

初版完成36项测试、13组离线场景和13组真实模式场景。首次真实检查12/13，修正无素材合理追问的过窄状态预期并增强证据要求后，同批日志复核13/13；原始记录保留。

本轮补充资料类型、字段、数值范围、保存重校验等10项回归，实际测试46/46通过，异常回归3/3通过。正式场景的新版本验证记录另存于 `examples/revision-offline/` 与 `examples/revision-live/`，不覆盖历史证据；完整结果见03-evaluation.md。接口替身与Mock不作为真实模型效果依据。

## 候选人贡献与投入

候选人自报累计投入约 **2.5小时**。这是本项目的个人参与估算，包含交流与评审过程；没有单独统计独立编码、手动执行命令和等待工具的分钟数，不将AI执行时间折算为个人手写代码时间。

| 工作 | 实际参与与责任 |
| --- | --- |
| 选题与交付范围 | 候选人确认第2题，选择先完成核心CLI链路 |
| 模型与凭据 | 候选人提供官方DeepSeek服务，在本地配置密钥；密钥未进入仓库 |
| 质量与隐私要求 | 候选人要求逐项对齐、启动演示、重试真实连接，并明确禁止上传隐私 |
| 工程实现 | AI完成主要源码、测试、资料、执行、文档及Git操作；候选人未声明独立手工实现全部代码 |
| 材料理解与复盘 | 按实际代码补充模块说明和问题分析，供候选人审阅与复现；文档不作为已经掌握知识的证明 |
| 异常诊断与迭代 | 候选人提出增加异常场景，随后委托AI继续完成；AI执行根因分析、修复与回归，个人未另行提交独立诊断记录 |

## 对实现的理解说明

理解材料见 [07-understanding.md](07-understanding.md)，覆盖模型与工具的分工、状态与幂等、预算时间口径、真实模型证据与Mock边界。它依据实际源码与运行记录整理，没有把尚未发生的个人修改写成履历。

本项目的关键判断是：模型可选择下一动作，硬性预算、截止时间和保存结果由代码与数据库核验；生成了脚本或估算可行，不等于已经保存方案。成功工具结果应保留，失败应成为下一轮模型观察。

## 本轮异常分析与修复

三类实际复现包括外部费率表、素材库更新和同请求ID修改预算。前两类缺陷已增加资料契约校验，返回不可直接重试的结构化错误，保留已成功步骤；第三类确认为合理业务保护，保留原方案，并验证使用新ID可以接受新预算。

根因、修改范围、前后差异和测试证据见 [09-debugging-resolution.md](09-debugging-resolution.md)。分析与代码修改由AI完成，原始故障快照及本轮结果分别保留。候选人可以依据保留的 [复现模板](08-debugging-lab.md) 继续实践，但本轮没有把这一步写为已发生的个人独立工作。

密钥仅保存在本地.env，Git和交付压缩包排除该文件；未把密钥作为测试素材或写入报告。
