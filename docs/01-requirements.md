# 01 · 需求

用户为内容运营人员，目标是在预算和截止时间内形成有素材依据、包含可编辑脚本和制作步骤的已保存方案。选择考核第 2 题，采用 CLI。

输入包括 request_id、主题、预算、计划起点与截止时间。预算是非负有限模拟单位，时间必须带时区，截止晚于起点。不推测缺失预算和时间，不擅改硬约束。

| 验收点 | 成功标准 |
| --- | --- |
| 正常完成 | 工具结果支持计划，预算和时间通过，确认提交后标记完成 |
| 缺预算或截止时间 | needs_input，明确缺字段，0 次模型调用，不保存 |
| 工具失败 | 实际失败可见，模型选择重试、替代或停止，保留成功结果 |
| 预算超限 | 替代方案重新估算；无解则 incomplete，显示缺口，禁止保存 |
| 重复执行 | 相同请求一份方案，返回原结果；同 ID 不同输入拒绝 |
| 截止约束 | 计算串行时间，超限选择更快方案或终止，不修改用户时间 |
| 执行上限 | 默认每次最多 12 轮，可配置 1~30，到限明确未完成 |
| 续跑（加分） | 检索、脚本与估算断点保留，失败后能复用 |

每个真实运行至少有“模型选择动作 → 工具执行 → 返回观察 → 模型调整或结束”的循环。预设骨架仅用于边界约束，不能用规则模拟的日志证明真实效果。

业务工具使用本地合成资料与函数。交付的 completed 仅表示方案已保存；制作任务仍为 planned。不做界面、线上部署、真实制作发布、多 Agent 或生产级并发运行时。
