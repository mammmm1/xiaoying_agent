# 08 · 异常定位练习

状态：**分析与回归已完成；2个资料校验缺陷修复，1个合理业务保护保持。**

候选人最初提出增加场景后自行分析，后续委托AI补齐分析、修复和验证。实际改进记录见 [09-debugging-resolution.md](09-debugging-resolution.md)。本练习保留独立资料、数据库和修复前后观察，默认使用离线Mock，不产生API费用，也不证明真实模型决策效果。

## 复现入口

在仓库根目录执行：

```powershell
python scripts/debug_lab.py --case E01
python scripts/debug_lab.py --case E02
python scripts/debug_lab.py --case E03
```

不传case时运行全部。新报告写入 `runtime/debugging/reports/`，数据库在runtime内，均被Git忽略。首次快照见 [examples/exercises](../examples/exercises/README.md)，修复后报告在after子目录。脚本退出码0表示回归检查通过、1表示检查未通过；业务未完成可能是正确预期。

## 三个场景

| 编号 | 业务情形 | 当前实际现象 | 分析目标 |
| --- | --- | --- | --- |
| E01 | 接入外部费率表后，预算10需要评估替代档次 | 修复前TypeError；现在INVALID_RATES，明确未完成、不保存 | 费用文本不能直接参与数字求和，消费资料前须验证契约 |
| E02 | 素材库更新后，相关素材仍能检索到 | 修复前KeyError；现在INVALID_ASSET_DATA，保留检索结果 | 检索命中不保证事实完整，脚本生成前检查所选素材 |
| E03 | 先完成一个请求，再用同一ID把预算10改成11 | STATE_CONFLICT，数据库保留首份方案 | 判断这是合理保护还是缺陷，说明重规划应如何标识新需求 |

专用覆盖资料位于 `data/debugging/`。未覆盖的文件使用正式合成资料。你可以对照资料、selected_actions、checkpoint_steps和异常frames；frames使用仓库相对路径，不包含电脑用户名或绝对路径。

## 建议排查顺序

1. 写出复现命令与预期行为，先区分“应当拒绝的业务请求”和“应当被明确处理的程序异常”。
2. 对照selected_actions与checkpoint_steps，找出最后成功的动作以及首次未形成正常观察的动作。
3. 根据相对路径和行号定位代码，再比较正式资料与演练资料，说明输入如何流向异常位置。
4. 提出最小修改范围：校验、工具结果、Runtime返回或请求使用方式，避免用吞掉所有异常掩盖根因。
5. 设计回归：原有正常链路仍可完成，异常应有明确错误与未完成状态；失败不能保存，成功结果应保留。
