# 02 · 方案

## 真实决策循环

输入校验 → 读取 SQLite 断点 → DeepSeek 选择一个工具 → 本地参数校验与执行 → 保存实际观察 → tool 消息回传 → 模型决定继续或 finish。

`agent.py` 管理轮数、反馈和日志；`models.py` 调用 HTTPS `/chat/completions`，使用 tools、tool_calls、tool_call_id，关闭 thinking；`tools.py` 承担业务约束；`store.py` 管理事务与断点。

模型负责查询、脚本形式、制作档次、失败后的下一动作和结束。系统承担工具白名单、参数和依赖检查、费率计算、预算时间硬约束。提示词采用先评估精细方案再调整的骨架；真实模式没有“预算超限就自动选 standard”的执行分支，也不会自动重试业务工具。

## 工具与成本

- search_assets：关键词检索合成素材；可改写查询或请求补充。
- generate_script：本地模板模拟服务，用已检索素材原文生成分镜，返回来源 ID，不编造产品效果。
- estimate_plan：依据费率表估算成本、串行时间、预算与时间缺口。
- save_plan：再次计算约束并提交 SQLite，返回已提交的实际记录。
- finish：结束任务；未保存不能 completed。

`data/rates.json`：素材整理 1/5 分钟，脚本 2/10，制作 premium 9/90、standard 5/45、basic 2/20，保存 0/1。总成本为 12、8、5，总时间为 106、61、36 分钟。

这是方案预算，不是真实按调用计费账本。失败不收费，反复本地模拟不新增费用，最终计划只计选定制作档次。真实模型 API token 单列，不与模拟单位混算。计划起点来自输入而非机器当前时间；真实运行起止另行记录。

## 动态路径

预算 20 时 premium 可保存；预算 10 时观察到 premium 成本 12 后，应保留脚本、选择替代并重新估算，standard 成本为 8。截止 45 分钟时，basic 36 分钟可行。无可行方案必须停止并说明缺口。工具错误回传模型，模型自行决定重试、替代或停止。

离线规则模拟器仅检验流程。真实路径必须查看实际 DeepSeek Trace，不能把以上期望写成已经发生的真实决策。

## 幂等与续跑

requests 保存请求指纹、模型来源、资料指纹和成功/失败步骤；plans.request_id 唯一，事务与 INSERT OR IGNORE 确保只有一份已保存记录。返回实际提交记录，不返回未提交候选。

相同请求已保存则直接返回，本次模型调用为 0；同 ID 不同输入拒绝。Mock、不同模型来源不混用断点。未完成断点使用的资料改变会拒绝续跑；已保存方案是历史快照，重新评估应使用新 ID。

脚本按素材、形式、资料指纹缓存；估算绑定脚本 ID，旧脚本估算不能保存新脚本。失败不会覆盖成功结果。

## 取舍与来源

原生 Python 标准库，无 Agent 框架及第三方运行依赖；实测 Python 3.12.7，支持 3.11+。SQLite 满足本地持久化，不宣称支持多执行器并发续跑。HTTP 不自动重试，超时可配置至 120 秒。工具注入失败发生在副作用前。

协议依据：[DeepSeek 接入](https://api-docs.deepseek.com/)、[Chat Completions API](https://api-docs.deepseek.com/api/create-chat-completion/)，核对日期 2026-10-28。未使用服务端 strict 模式，参数在本地校验。
